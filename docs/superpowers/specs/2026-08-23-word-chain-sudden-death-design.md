# 끝말잇기 첫 탈락 종료 — 걸린 사람을 찾는 게임

선행 문서: [게임 진행](2026-08-23-word-chain-game-design.md) · [좌석 순서](2026-08-23-word-chain-seat-order-design.md)

## 1. 무엇을 바꾸나

지금은 서바이벌이다 — 탈락자가 나와도 남은 사람이 2명 이상이면 판이 계속되고, 마지막 한 명이
승자다. 이걸 **누구든 탈락하는 순간 판이 끝나는** 방식으로 바꾼다.

관점이 뒤집힌다. 승자 한 명을 찾는 게임에서 **걸린 사람 한 명을 찾는 게임**으로. 끝말잇기를
실제로 노는 방식(걸린 사람이 벌칙)과 이쪽이 맞는다.

**옵션이 아니라 교체다.** 서바이벌 모드는 사라진다.

범위 밖 — 서바이벌·첫탈락 모드 선택, 벌칙 안내, 전적.

## 2. 결정 요약

| 결정 | 왜 |
|---|---|
| 탈락 즉시 판 종료. 결과는 `loserId` | 승자를 세는 게임이 아니라 걸린 사람을 찾는 게임이다 |
| `winnerId` → `loserId` 로 계약 변경 | 이름이 거짓말하면 안 된다. "생존자 중 대표 승자"는 억지다 |
| `eliminated` 는 배포 창 동안만 계약에 남긴다 | 창이 열려 있는 동안 구 프론트의 `eliminated.includes` 가 죽는다. 창이 닫히자 양쪽에서 뺐다 |
| 넘기기·참가자 끊김도 판을 끝낸다 | 탈락 경로마다 규칙이 다르면 설명이 안 된다 |
| 모드 옵션을 두지 않는다 | 옵션마다 테스트 조합이 배가 된다. 요청이 교체다 |

## 3. 규칙

**`eliminate` 가 곧 판 종료다.** 남은 인원을 세지 않는다.

```
지금:  alive.size() == 1 ? 승자 확정 : 다음 차례로 계속
바꿈:  탈락 즉시 종료. loserId = 탈락자, Turn.NONE, status → WAITING
```

탈락 경로는 넷이고 **전부 같은 결과**다 — 시간 초과, 기회 소진(한 턴 3번 오답), 넘기기,
참가자 연결 끊김.

- **관전자 퇴장은 판에 영향 없다.** `giveUp` 의 `turnOrder.contains` 가드가 이미 그렇게
  동작하는데, 이 가드가 이제 판 전체를 지키는 자리가 된다
- **2인 판은 사실상 안 바뀐다.** 지금도 첫 탈락이 곧 종료였다. 문구만 "남은 사람 승리"에서
  "걸린 사람 탈락"으로 바뀌고, 이로써 2인과 N인의 결과 모양이 처음으로 같아진다
- 다음 판은 지금과 같다 — 대기실로 돌아가 준비하고 방장이 시작한다. 탈락자도 정상 참가한다

## 4. 계약

```
GameState.winnerId : number | null      →      GameState.loserId : number | null
```

- `turnOrder` 그대로 — 관전자 판별에 계속 쓴다
- **`eliminated` 는 배포 창이 닫힌 뒤 양쪽에서 제거했다** (백엔드 `697e702`). 창이 열려 있는
  동안에는 구 프론트가 `eliminated.includes` 를 부르므로 남겨야 했고, 새 프론트가 배포되어
  읽는 곳이 사라지자 뺐다. 순서 위험은 없다 — 아무도 안 읽는 필드가 사라지는 것이다
- 배너 문구는 `OO 님 탈락`

## 5. 연쇄로 죽는 코드 — 이 변경의 덤

탈락이 곧 종료라서 **"게임 중인데 탈락한 사람"이라는 상태 자체가 사라진다.**

| 죽는 것 | 왜 |
|---|---|
| `ELIMINATED` · `WINNER` phase | 게임 중 도달 불가. `TURN` · `ALIVE` · `SPECTATOR` 셋만 남는다 |
| 연단 `탈락` · `승리` 배지 | 위와 같다. `관전` 은 남는다 |
| `playerPhase` 의 `winnerId` 분기 | 판이 끝나면 무대가 대기실로 돌아가므로 phase 가 안 그려진다 |
| `turnAfter` 의 탈락자 건너뛰기 | 건너뛸 탈락자가 없다 (백엔드 재량) |

게임 진행 스펙에서 잡았던 "`탈락` 배지가 다음 판까지 남아 방장이 죽어 보인다" 류의 버그
자리가 통째로 없어진다.

## 6. 문구 둘

| 자리 | 지금 | 바꿈 |
|---|---|---|
| 결과 배너 | `OO 님 승리` | `OO 님 탈락` |
| 넘기기 확인창 | `넘기면 되돌릴 수 없습니다.` | `넘기면 탈락해 이번 판이 끝납니다.` |

넘기기의 무게가 커진다 — 3인 이상에서 넘기기는 모두의 판을 끝내고 본인이 걸린 사람이 되는
행동이다. 확인창이 그걸 말해야 한다.

## 7. 프론트 구조

- `types.ts` — `winnerId` → `loserId`
- `playerPhase.ts` — 유니온이 `TURN | ALIVE | SPECTATOR` 로 준다. `winnerId`·`eliminated`
  분기 삭제
- `WinnerBanner` → `ResultBanner` 로 개명, 문구 교체
- `PlayerPodium` — `탈락`·`승리` 라벨 삭제, `관전` 유지
- `RoomView` — `finished` 판정과 배너 배선이 `loserId` 를 본다. 넘기기 확인창 문구

## 8. 배포 순서 — 백엔드 먼저, 프론트 곧바로

계약 필드가 바뀌므로 사이에 창이 있다. 구 프론트 + 신 백엔드에서:

- **판 종료 후** — 배너만 안 뜬다. `finished && winner` 가드가 `winner`(못 찾음)를 걸러
  크래시 없이 조용히 넘어간다 (확인함)
- **판 진행 중** — `winnerId` 가 `undefined` 라 `undefined !== null` 이 참이 되어 전원이
  탈락으로 보인다

두 번째 때문에 **배포 창에서 판을 돌리지만 않으면 된다.** 프론트를 곧바로 이어 올려 몇 분
안에 닫는다.

## 9. 검증

| 확인할 것 | 판별점 |
|---|---|
| 3인 첫 탈락 종료 | 한 명이 시간 초과되면 그 즉시 판이 끝나고 배너가 그 사람을 알린다 |
| 배너 | `OO 님 탈락` |
| 넘기기 | 확인창 문구가 바뀌었고, 누르면 판이 끝난다 |
| 관전자 퇴장 | 판이 계속된다 |
| 다음 판 | 탈락자가 정상 참가한다 |
| 관전 배지 | 게임 중 입장한 사람에게 여전히 붙는다 |

## 10. 폐기한 대안

| 대안 | 왜 안 하나 |
|---|---|
| 서바이벌 · 첫탈락 모드 옵션 | 옵션마다 테스트 조합이 배가 된다. 요청이 교체다 |
| `winners` 배열 (생존자 전원 승리) | "여럿이 이겼다"는 메시지가 약하고 계약이 복잡해진다 |
| `winnerId` 이름 유지, 의미만 변경 | 이름이 거짓말한다 |
| `eliminated` 계약 제거 | 구 프론트가 죽는다. 이득 없음 |
| 끊김은 판 유지, 넘기기만 종료 | 탈락 경로마다 규칙이 갈리면 설명도 테스트도 배가 된다 |
