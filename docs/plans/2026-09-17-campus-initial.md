# 공장 정문 3D 로그인 배경

## 범위와 책임

첨부 사진의 은색 공장·주황색 띠·유리 경비실·가로수를 입체적인 정문 장면으로 표현한다. 사람이 보행 게이트를 통과하고 차가 도로를 오간다. 기존 로그인·회원가입 폼과 인증 계약은 유지한다. 기존 하네스 작업과 관리자 변경은 보존하며 커밋·푸시는 범위 밖이다.

- 기준: `main`, `d017499026195fcae38292e30b54059bafc33865`. 이번 시작 시점의 335개 파일을 로컬 `company-backend/build/login-campus-stage/before`와 `baseline.json`에 보관했다. [이전 하네스 완료 기록](2026-09-17-frontend-harness.md)을 보존했다.
- `AuthLayout`은 화면 배치·폼·배경 제어를 조립한다. 장면의 생성·해제와 프레임은 인증 feature의 campus 컴포넌트가 관리하며 정적 환경과 이동 객체를 분리한다.
- 설치된 Three.js를 지연 로딩한다. 외부 모델·이미지 다운로드나 신규 의존성 없이 코드로 장면을 만든다. 배경이 실패해도 폼은 유지한다.
- 사진의 건축 요소를 참고한 스타일화된 장면이며 실제 사업장·실시간 사람/차량 데이터를 재현하는 기능은 아니다.

## 실행 순서

1. 시작 파일을 보존하고 정적 장면·이동 객체를 병렬 구현한다.
2. 폼 조립, 반응형 배치, 배경의 로딩·실패·해제를 연결한다.
3. 실제 Chromium에서 장면을 보고 구성과 움직임을 조정한다. 증거는 정적 확인·mock 인증·실제 렌더링을 구분한다.
4. 관련 검증과 독립 읽기 전용 리뷰를 진행한 뒤 검증한 파일만 실제 프런트에 반영한다.

## 결정과 근거

- 이미 사용 중인 Three.js의 실제 메시·광원·그림자를 재사용한다. 2D 배경 사진은 사람과 게이트의 공간 관계를 구현하기 어렵고, 외부 모델은 추가 로딩·출처 관리 비용이 있다. 텍스처 없는 코드 모델은 사진보다 단순해지는 단점이 있다.
- 장식 이동은 폼 사용을 방해하지 않게 일시정지를 제공한다. [W3C의 지속 애니메이션 제어 지침](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)을 참고했다.
- 렌더러·기하·재질·텍스처와 이벤트를 해제하며 화면 해상도와 그림자 크기를 제한한다. [Three.js 렌더러 문서](https://threejs.org/docs/pages/WebGLRenderer.html)를 기준으로 설치 버전의 타입과 브라우저 실행을 확인한다.

## 검증·리뷰와 남은 범위

- `yarn verify:all`: 종료 코드 0. Vitest 63파일·553건, 구조 도구 7건·평가 입력 도구 5건, 실제 src 경계, 포맷·lint·타입·Vite 빌드, Chromium 9건 통과. 로컬 로그는 `company-backend/build/login-campus-stage/verify-stage.log`에 있다.
- 이후 표시 폭·모바일 제목·태블릿 배치만 조정하고 타입·배포 빌드와 Chromium 9건을 재확인했다. `build-final.log`, `browser-final.log`에 근거가 있다. 변경 파일만 포맷 검사하며 기존 검사 규칙은 낮추지 않았다.
- 실제 브라우저 캡처는 로컬 `company-backend/build/login-campus-stage/captures/`의 `login-desktop.png`, `login-motion.png`, `login-tablet.png`, `login-mobile.png`, `signup-mobile.png`, `login-ultrawide.png`다. 페이지 오류 0, 모바일 가로 넘침 없음. API는 mock이며 실제 백엔드 인증·쿠키 검증이 아니다.
- 리뷰의 넓은 화면 반복 지점 노출 지적을 수용했다. 페이지 표시 폭을 1920으로 제한하고 최소 높이를 유지해 카메라 시야를 제한했다. 3440×900에서 실제 표시 폭 1920과 캡처를 확인했다. 도로·보도는 ±44, 차량 반복은 ±46, 보행 반복은 ±40 또는 건물 내부다.
- 수정 후 독립 재리뷰에서 반복 지점 노출이 해결됐음을 확인했으며 추가 P1/P2는 없었다. 표시 범위 최대 약 ±25.71에 대해 반복 위치의 투영 좌표는 보행자 28.30·차량 29.30 이상으로 화면 밖이다. 실제 탭 숨김의 실행 근거는 미검증으로 유지한다.
- 일시정지·동작 줄이기는 캔버스의 시간 차 픽셀 비교, 화면 밖 중단/복귀는 실제 WebGL clear 호출 수로 확인했다. 실제 WebGL 생성 실패·컨텍스트 손실을 주입해 폼 입력과 로그인이 유지됨을 확인했다.
- **AC-4의 실제 비활성 탭 전환은 미검증이다.** headless 및 별도 화면 밖 Chromium 창에서 탭 전환·최소화·강제 포커스 설정 해제를 시도했지만 `document.visibilityState`가 `visible`로 남아 전제 조건을 만들지 못했다. 실제 숨김을 검증했다고 보고하지 않는다. `visibilitychange` 분기와 RAF 중단은 정적 리뷰했으며 일반 브라우저에서 숨김→복귀의 추가 확인이 남는다. 이를 제품 결함이나 통과로 바꾸지 않는다.
- 500kB 초과 번들 경고는 남는다. 기존 Three.js를 재사용하고 캠퍼스는 별도 지연 청크로 분리했지만 로그인에서 최초 로딩 시 Three.js가 추가로 내려온다. 실제 저사양 모바일·Safari 성능은 측정하지 않았다.

- 반영 상태: 실제 company-app 반영·대조 완료. 기존 관리자·하네스 작업과 의존성은 유지했으며 커밋·푸시는 하지 않았다.
- 실제 반영: 작업 시작 파일 335개를 대조하고 24개 경로만 반영했다. 19개 쓰기·웨이퍼 전용 5개 삭제이며 모든 반영 파일을 해시로 확인했다. 실제 프런트의 `format:check`와 타입·배포 빌드도 종료 코드 0으로 성공했다. 로컬 로그는 `company-backend/build/login-campus-stage/verify-frontend.log`다.
- 판정: 요청한 화면 구현을 실제 저장소에 반영했다. AC-4 일부 실검증이 남아 전체 계획을 완료로 처리하지 않는다.
