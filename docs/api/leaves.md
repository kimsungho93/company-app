# 휴가 · 공휴일 API 명세

갱신일: 2026-08-19
상태: **구현 완료.**

프론트(`front/company-app`)와 백엔드(`backend/company-backend`)가 함께 참조한다. 계약이 바뀌면 이 문서를 먼저 고친다.
인증은 [auth.md](auth.md), 사용자·관리자는 [users.md](users.md) 에 있다.

## 1. 결재 절차가 없다

휴가를 내면 **바로 확정**되어 달력에 뜬다. 상태 컬럼이 없다. 결재가 필요해지면 그때 추가한다.

대리 등록·대리 취소도 없다. 등록·삭제는 토큰 주인의 것만이다.

## 2. 휴가 종류

| 코드 | 화면 표기 | 기간 |
|---|---|---|
| `ANNUAL` | 연차 | 여러 날 가능 |
| `HALF_DAY_AM` | 오전반차 | **하루만** |
| `HALF_DAY_PM` | 오후반차 | **하루만** |
| `OFFICIAL` | 공가 | 여러 날 가능 (경조사) |

**한글은 화면 표기일 뿐 API 에 싣지 않는다.** 프론트의 `LEAVE_KIND_LABEL` 이 코드를 문구로 옮긴다.

## 3. 엔드포인트

| 메서드 | 경로 | 권한 | 성공 |
|---|---|---|---|
| GET | `/api/leaves?from=&to=` | 로그인 | 200 |
| POST | `/api/leaves` | 로그인 (본인) | 201 + 본문 |
| DELETE | `/api/leaves/{id}` | 로그인 (본인) | 204 |
| GET | `/api/holidays?from=&to=` | 로그인 | 200 |
| POST | `/api/holidays` | ADMIN | 201 + 본문 |
| DELETE | `/api/holidays/{id}` | ADMIN | 204 |

```json
// GET /api/leaves
[{ "id": 12, "userId": 3, "name": "박철수", "kind": "ANNUAL",
   "startDate": "2026-08-18", "endDate": "2026-08-21" }]

// POST /api/leaves
{ "kind": "ANNUAL", "startDate": "2026-08-18", "endDate": "2026-08-21" }

// GET /api/holidays
[{ "id": 4, "name": "설날", "startDate": "2027-02-06", "endDate": "2027-02-08" }]
```

**`POST` 는 201 에 만들어진 객체를 담아 돌려준다.** 가입이 본문 없이 201 을 주는 것과 다르다 — `id` 가 없으면 방금 만든 항목을 지울 수 없다.

**`userId` 를 반드시 본다.** 프론트가 삭제 버튼을 그릴 때 이름으로 비교하면 동명이인이 남의 휴가를 지운다.

**`name` 은 `null` 일 수 있다.** 서버가 사용자를 찾지 못하면 비워서 내려준다.

## 4. 조회는 포함이 아니라 겹침이다

```sql
WHERE end_date >= :from AND start_date <= :to
```

기간이 조회 창을 **걸치기만 해도** 나온다. `start_date BETWEEN from AND to` 로 짜면 8/18~8/21 휴가를 `from=2026-08-19` 로 물었을 때 사라진다.

**프론트가 보내는 `from`·`to` 는 그 달의 1일·말일이 아니라 6주 격자의 첫 칸과 마지막 칸이다.** 2026년 8월 달력이면 `2026-07-26 ~ 2026-09-05` 다. 앞뒤 달이 물려 오지 않으면 격자 가장자리가 빈다.

`from` 이나 `to` 가 없으면 400 `INVALID_INPUT` 이다.

## 5. 겹침은 서버가 판정한다

한 사람은 하루에 하나다. 오전반차와 오후반차를 나눠 내면 하루를 통째로 쉬는 것이라 연차로 내야 하고, 연차 기간 안에 반차를 겹쳐 낼 수도 없다.

**프론트에서 미리 검사하지 않는다.** 화면이 가진 것은 보이는 달의 목록뿐이라, 범위 밖 휴가와의 겹침을 놓치고 "괜찮다"고 안내한 뒤 서버가 409 를 낸다. 오히려 틀린 안내다.

백엔드는 두 겹으로 막는다 — 저장 전 조회, 그리고 `leave_days` 의 `(user_id, date)` 유니크 제약. **조회만으로는 동시 요청에 뚫린다**(실측 확인). 마지막 방어선은 DB 다.

## 6. 공휴일

**법정공휴일(신정·삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절)은 서버가 갖지 않는다.** 프론트 `shared/lib/holidays.ts` 에 상수로 박혀 있다. 이 API 가 다루는 것은 관리자가 손으로 지정하는 것뿐이다 — 창립기념일, 그리고 설·추석처럼 음력이라 그 상수에 넣지 못한 날들.

화면은 둘을 합쳐 그리고, **서버 것이 우선**이다. 법정공휴일이 있는 날에는 지정·해제 UI 가 뜨지 않는다.

**연휴는 기간 한 건이다.** 사흘짜리를 행 세 개로 쪼개지 않으므로 해제하면 사흘이 한 번에 사라진다.

**겹침을 막지 않는다.** 같은 날에 두 건이 있으면 나중 것이 화면에 뜬다. 해제하면 되돌아간다.

조회는 전 직원이 한다. 달력에 빨간 날을 그려야 하므로 관리자로 막으면 안 된다.

## 7. 날짜는 `LocalDate` 다

`YYYY-MM-DD` 문자열이고 시간대가 없다.

`GET /api/admin/users` 의 `createdAt` 은 `Instant` 라 UTC(`...Z`)로 나가지만 **휴가 날짜는 그렇지 않다.** 같은 방식으로 다루면 KST 에서 하루 밀려 8월 18일 휴가가 17일에 뜬다.

## 8. 오류

`{ code, message }` 형태이고 `message` 는 화면에 그대로 띄운다.

| HTTP | `code` | 상황 |
|---|---|---|
| 400 | `INVALID_INPUT` | `from`·`to` 누락, 종류 누락, 공휴일 이름이 비었거나 12자 초과 |
| 400 | `INVALID_DATE_RANGE` | 종료일이 시작일보다 이름 |
| 400 | `HALF_DAY_MUST_BE_SINGLE_DAY` | 반차를 여러 날로 냄 |
| 400 | `LEAVE_RANGE_TOO_LONG` | 366일 초과 |
| 403 | `FORBIDDEN` | 남의 휴가를 지움 · 관리자가 아닌데 공휴일을 건드림 |
| 404 | `LEAVE_NOT_FOUND` · `HOLIDAY_NOT_FOUND` | |
| 409 | `LEAVE_OVERLAP` | 본인 휴가와 겹침. `message` 가 무엇과 겹치는지 알려준다 |

## 9. 프론트 연결 지점

| | |
|---|---|
| API 슬라이스 | `features/leave/api/leaveApi.ts` |
| 태그 | `Leaves` · `Holidays` — 등록·삭제가 무효화한다 |
| 법정공휴일 | `shared/lib/holidays.ts` |
| 종류 라벨 | `features/leave/model/types.ts` 의 `LEAVE_KIND_LABEL` |

낙관적 갱신을 쓰지 않는다. 등록·삭제가 팝업을 닫으며 끝나고 목록도 짧아 롤백 코드를 두는 것보다 재조회 한 번이 싸다.

## 10. 아직 없는 것

- 결재 절차, 연차 잔여일수
- 공공데이터포털 특일정보 연동 — 법정공휴일이 서버로 옮겨 가는 날. 키 관리와 캐싱이 서버 일이라 결국 이쪽으로 온다
- 부서·팀 필터, 일괄 등록
