# 프론트 변경 검증

[AGENTS.md](../../../AGENTS.md)와 [README.md](../../../README.md)의 명령·검증 선택 표를 기준으로 한다. 실제 스크립트와 도구 버전은 `package.json`·`yarn.lock`을 확인한다. 커밋·푸시·배포는 자동 실행하지 않는다.

요청·PLAN의 조건 ID와 실제 diff·새 파일을 대조하고 기존 변경과 이번 범위를 구분한다. 검증할 사용자 행동과 실패 결과에 맞는 가장 좁은 검사부터 선택한다. 버그는 가능한 경우 수정 전 실패·수정 후 통과하는 회귀 테스트로 확인한다. 테스트·검사·CI를 바꿔 통과시키려 하지 말고 변경 이유와 유지되는 보장을 확인한다.

- 일반 코드 변경은 관련 Vitest 테스트와 포맷·lint·build를 실행한다. import·별칭·구조 변경은 `check:architecture`와 `test:architecture`를 포함한다. 공통 기준은 `verify`, 여러 기능이나 도구·의존성 변경은 `verify:all`과 해당 도구 테스트로 확인한다.
- UI 동작·공통 대화상자·인증·연결 변경은 관련 브라우저 흐름을 확인한다. 기존 Playwright smoke가 변경을 다루는지 먼저 확인하고 키보드·포커스·테마·반응형 등 조건에 필요한 관찰을 보완한다. 단순 문구 변경의 선택적 브라우저 미실행을 필수 실패로 바꾸지 않는다.
- 문서만 바뀌면 참조·명령·설정의 정합성과 포맷을 확인한다. 리뷰·검증 판단 기준을 바꿨다면 관련 [고정 평가 사례](../../../evals/harness/README.md)와 정상 대조군을 사용한다. 입력 생성 테스트는 에이전트 의미 판단의 검증이 아니다.

Playwright에는 설치된 브라우저가 필요하다. README의 준비 명령과 현재 설정의 서버·포트를 확인한다. 기존 서버를 임의 종료하거나 운영 계정을 테스트에 쓰지 않는다. 환경이 없으면 가능한 검증을 마치고 남은 조건을 미검증으로 기록한다. 실패 로그의 첫 원인과 보고서를 확인해 명령/설정 오류·환경 문제·제품 결함을 구분한다. 이전 보고서·캐시 결과·테스트 없는 성공을 새 실행 성공으로 보고하지 않는다.

증거의 범위를 구분한다. Vitest mock은 모의 입력에 대한 코드·컴포넌트 동작, Playwright mock REST smoke는 실제 Chromium의 화면 흐름을 확인한다. 실제 서버 권한·쿠키 회전·STOMP 연결이 요구되면 실제 백엔드와 별도 실행해야 한다. REST 필드·오류·권한·날짜·소켓 이벤트가 바뀌면 `docs/api`와 실제 백엔드 사용처를 대조하고 검증한 서버/프론트 상태를 남긴다. 토큰·비밀번호·개인정보는 근거에 복사하지 않는다.

실행 후 명령·시점·종료 결과·보고서 또는 관찰 내용을 검증 당시 코드 상태와 연결한다. HEAD와 실제 diff·새 파일, 필요하면 관련 파일 해시를 사용한다. 이후 관련 코드가 바뀌면 영향을 받은 조건만 재확인한다. 새로운 실패·변경·미해결 우려가 없으면 검사를 이유 없이 반복하지 않는다.

PLAN이 있으면 주 에이전트가 같은 조건 ID에 근거와 `통과·실패·미검증·해당 없음`을 기록한다. 실행 조건에 정적 확인만 있거나 환경 부족·오래된 근거가 있으면 미검증이다. 필수 실패·미검증은 완료로 처리하지 않고 권고 조건과 해당 없음의 이유는 별도 보고한다. 다른 작업의 PLAN을 덮어쓰지 않는다. 읽기 전용 역할에서 이 스킬을 참조했다면 실행·수정은 맡지 않고 필요한 검증만 제안한다.
